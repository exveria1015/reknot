# Reknot

[English](../docs/README.md) | 日本語 · [ドキュメント一覧](INDEX.md)

**アプリを動かしたまま、Rust のロジックを編集して試す。**

Reknot（リノット、旧 flow-reloader）は、ローカル開発向けのホットリロード SDK です。
接続や画面、残しておきたい状態をホスト側に置き、変更する処理をロジックとして分けます。
ロジックを編集して保存すると、ビルドと検査の成功後、新しい処理へ切り替わります。

たとえば Bot の返信や入力チェックを、接続を張り直さずに調整できます。
ハンドラーは通常の Rust 関数として書き、属性を付けて登録します。

## まず動かす

Rust 1.95 以上と Cargo を用意し、このリポジトリのルートで実行します。
最初は、外部アカウントやトークンが不要なコンソール Bot を使います。

```sh
cargo run -p typed_bot_host --locked
```

初回ビルドが終わり、`Typed bot ready.` と表示されたら、次を試してください。

1. `hello` と入力する。`logic-v1 / message 1: HELLO` と返信されます。
2. [ロジックのソース](../examples/typed_bot_logic/src/lib.rs) にある `logic-v1` を `logic-v2` に変えて保存する。
3. `New events use generation ...` の表示を待ち、もう一度入力する。今度は `logic-v2` で返信されます。

`/summary` を入力すると、直近100件までの入力履歴を確認できます。ロジックを更新しても、ホストに置いた履歴は残ります。
`/quit` で終了します。

ビルドに失敗した場合は、動作中のロジックがそのまま使われます。エラーを直して保存すると再試行します。

## 自分のアプリを作る

リポジトリのルートから、ひな形を生成できます。

```sh
cargo run -p reknot --bin reknot-new --locked -- ../my-bot --sdk-path ./reknot
cd ../my-bot
cargo run
```

生成先は新しいディレクトリを指定してください。初回実行で作られる `Cargo.lock` もバージョン管理し、
以降は `cargo run --locked` を使います。

プロジェクトは、役割の異なる3つの crate に分かれています。

| 場所 | 書くもの |
| --- | --- |
| `logic` | 返信や計算など、編集して試したい処理 |
| `protocol` | ホストとロジックで共有する入力・戻り値の型、処理の名前と契約の版 |
| `host` | 接続、イベント登録、継続する状態、更新処理を動かすループ |

まずは `logic/src/lib.rs` の返信を変えて保存してください。
生成したアプリでは `/count` で入力件数を確認できます。
SDK の参照先やハンドラーの書き方は、[型付きハンドラー入門](TYPED_HANDLERS.md) で説明しています。

## 更新すると何が変わるか

型付き API は、1つの crate／DLL をまとめて更新します。
その中のハンドラーと補助関数は同じ版のコードで動きます。読み込まれたロジックの版を **世代** と呼びます。

新しい世代へ切り替えた後も、すでに受け付けた処理は旧世代で完了まで続きます。
この方式が **Drain** です。ホストに登録した呼び出し口は維持され、以後の処理を新しい世代へ渡します。
別スレッドからキューを通して呼ぶ場合は、所有スレッドが実行を受け付ける時点で世代を選びます。

型付き API でも、登録ワーカーを止め、型付きチェックポイントから作り直す **Restart** を利用できます。
登録・移行・復旧は [型付き Restart](TYPED_RESTART.md) を参照してください。既定の更新方式は Drain です。

## 利用前に知っておくこと

ローカルの信頼できる Rust コードを扱う、開発中の SDK です。Rust API は今後変わる可能性があります。
ホストとロジックは同じ SDK でビルドしてください。対応環境は [互換性と対象範囲](COMPATIBILITY.md) にまとめています。

入力・戻り値の形式や意味を変えるときは、共有する契約の版を上げ、ホストも再起動します。
生成したスキーマにより、同じ Rust 型名のままの構造変更も検出します。意味の一致までは証明しません。
詳しくは [契約エラーとスキーマ](CONTRACTS_AND_SCHEMAS.md) を参照してください。

DLL は既定で保持されます。累積ロード試行の上限は既定32回で、失敗したネイティブロードも数えます。
上限に達したら開発ホストを再起動してください。[明示的な DLL 回収](UNLOAD_SAFETY.md) は別途提供していますが、
自動回収や、実行中の処理・外部送信の巻き戻しは行いません。
