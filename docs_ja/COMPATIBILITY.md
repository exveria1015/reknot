# 互換性と対象範囲

[English](../docs/COMPATIBILITY.md) | 日本語

Reknot は、ローカル開発中に信頼済みの Rust ロジックを更新するための、公開前の SDK です。
リリースまでは Rust API が変わる可能性があります。ネイティブロードと静的リンクでは、
同じメッセージ API と所有の契約を使います。

## ツールチェーンと対象環境

| 構成 | 必要条件・検証の設定 |
| --- | --- |
| コア crate と Bevy 以外のサンプル | 宣言上の最小 Rust は1.95。コアの最小バージョン検査を CI に設定 |
| Bevy サンプル | Rust 1.97.1 以上。ウィンドウ・GPU を使わない統合例 |
| SQLite 移行サンプル | bundled SQLite 用の C コンパイラ |
| Tauri GUI | 各 OS の Tauri ビルド環境。Windows は WebView2。npm・Tauri CLI は不要 |
| ネイティブのコア・サンプル | Windows・Linux の CI を設定 |
| GUI バックエンド | Windows・Linux CI で、実ウィンドウを開かずに検査 |
| GUI 操作 | Linux の WebView を Xvfb で起動。編集・Drain／Restart・ビルドエラー復帰を検査 |
| macOS・その他の環境 | このリポジトリでは CI を設定していない |

CI の設定は検査対象を示すもので、特定の版の成功を保証するものではありません。
実行方法は [テスト](TESTING.md)、設定は [ワークフロー](../.github/workflows/ci.yml) を参照してください。
実ウィンドウの表示と操作は、[GUI ガイド](TAURI_GUI_LAB.md) の手順で別途確認します。

## API と ABI

通常の関数には `handler` / `export_handlers!` と `typed::ModuleHost` を使います。
ホスト資源や受付を直接制御する低レイヤーの入口は、`reload_handler`、`HostResources`、`RequestRouter`、`RequestTask` です。
型付き API も同じ ABI と所有の契約に従います。
ロード方式は Debug／Release と独立して feature で選びます。
指定方法は [ビルド構成](API_REFERENCE.md#ビルド構成) を参照してください。

| 境界 | 版・契約 |
| --- | --- |
| Handler ABI | 5。既存 prefix を維持し、任意のメタデータ末尾 v1 を追加 |
| 型付き契約 | v2。Serde 両方向のスキーマを含み、`JsonSchema` が必要 |
| ホストサービス ABI | 2 |
| タスク制御 ABI | 2 |
| ホストとロジック | 同じ SDK と、互換性のあるターゲット・ツールチェーンでビルド |
| サービス・入力・初期化・チェックポイントの形式 | アプリケーションが定義し、必要な箇所で明示的に版を管理 |

ABI メタデータは不一致の検出に使います。ネイティブコードの安全性や、ペイロードの意味までは検査できません。
ネイティブロードは `unsafe` であり、初期化・終了処理・コールバック・所有データ・コードの寿命を含め、
SDK の契約を満たす必要があります。詳細は [API リファレンス](API_REFERENCE.md)、
API の変更点は [変更履歴](../CHANGELOG.md) を参照してください。

## アプリケーションが設計すること

- DLL のタスクとホスト資源を所有スレッドで扱うこと。別スレッドからは型付きの `HandlerClient` で要求を渡せますが、
  DLL のタスクや資源ハンドル自体を移動することはできません。
- poll、キャンセル後の後処理、登録した子タスク・コールバックの終了待ちを進めること。
  外部の処理は明示登録し、未登録の独自 spawn を自動発見する前提にしないでください。
- サービスと状態の形式、キューの上限、停止期限を定義すること。
  Restart では協調停止を使い、登録ワーカーだけを再生成します。
- ホスト資源の移行に必要な排他、トランザクションの rollback、永続データからの復旧を実装すること。
  DB の commit と Router の切り替えは、クラッシュ時に一括して確定する処理ではありません。
- 開発セッションの長さを区切ること。KeepLoaded と累積ロード予算には失敗したロードも含まれます。
  枯渇時はプロセスを再起動し、終了後の適格なコピーは必要に応じて明示的に掃除します。
- 明示回収を使う場合は、外部 Waker の帰還、TLS、依存先等の終了条件をホストで確認すること。
  `unsafe reclaim_native_image` の契約は [DLL の寿命](UNLOAD_SAFETY.md) を参照してください。

本番配信、クラッシュ隔離、任意 Future のスタック移送、外部副作用の自動巻き戻し、
終了しない処理の強制停止、DLL の自動アンロードは現在の対象外です。
復旧方法は [開発時の運用](DEVELOPMENT.md)、コピーの扱いは [保持量の観測と掃除](RETENTION_AND_CLEANUP.md) を参照してください。
